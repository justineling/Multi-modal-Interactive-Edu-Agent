4检索与路由

这一篇讲两个决定产品质量的核心算法：怎么找到对的课本片段，怎么判断"课本到底有没有覆盖"。后者曾经出过一次严重的误判。

检索管线四步

① 章节精确过滤
有 section_code 时先 SQL 过滤
↓
② 双通道打分
BM25（词面）+ 向量（语义）
↓
③ 加权融合排序
取 Top-K（默认 8）
↓
④ 覆盖判定
实词命中率 → 三态之一

注意第 ④ 步不看分数，只看"实词命中"。这是本项目最关键的一个设计决定，下面详细说。

混合检索的打分公式

final_score = 0.35 × bm25_norm      # 词面匹配（专有名词、人名、术语）
            + 0.45 × cosine          # 语义相似（同义改写、跨语言）
            + 0.15 × section_bonus   # 章节号命中加分
            + 0.05 × page_bonus      # 页码邻近加分

为什么需要两个通道

场景BM25 表现向量表现
问「Malayan Union 苏丹」✅ 强（专有名词精确匹配）一般（可能匹配到同主题别的段落）
问「英国人为什么要把各州合并」❌ 弱（课本里没这几个字）✅ 强（语义能对上"联邦化动机"）
问「4.1.3 讲了什么」❌ 弱（课本不写章节号）❌ 弱

第三种情况靠元数据过滤解决：先按 section_code 精确捞该节所有切片， 再在节内做混合排序。这就是"目录树精确锚定"的实现。

向量是本地生成的确定性 embedding。用 blake2b 把 token 哈希到 1536 维桶， 词频累加后 L2 归一化。它不是真正的语义模型，但胜在零依赖、零成本、同输入必然同向量。 接真实 embedding 只需改 EMBEDDING_MODE=remote。

踩过的坑：BM25 归一化为什么不能用相对值

这是一个真实发生过、并且差点让整个产品卖点失效的 bug。

最初的实现（错的）

bm25_norm = bm25 / max(bm25 over all candidates)   # 相对归一化

看起来合理：把最高分归一到 1.0，其他按比例缩放。但有个致命后果——

候选集里分数最高的那篇永远得 1.0。于是任何问题（包括完全无关的）都能拿到 0.35 × 1.0 = 0.35 的基础分。NO_MATCH 永远不可能触发。

实测「量子纠缠的退相干时间是多少」得 0.380 分，被判成 PARTIAL_OR_BEYOND—— 系统会说"课本部分覆盖"，然后可能编造页码。这直接摧毁了产品最核心的"严格按课本"承诺。

第一次修复（还不够）

bm25_norm = bm25 / max(ideal_score, actual_max)
# ideal_score = Σ idf（查询词全部命中、文档为均值长度时的理论上限）

这次好多了，无关问题分数降到 0.216。但只解决了一半。

新问题：ideal 只累加"语料里确实存在"的查询词。当查询有 21 个词却只命中 3 个单字时， 分母被压得极小，bm25_norm 反而逼近 1.0：

"怎么用 Rust 写一个 WebAssembly 模块"   → bm25_norm = 0.998 → 总分 0.4016
"Malayan Union 对宪制发展的长期影响"    → 总分 0.3605

// 无关问题的分数，比真正需要拓展的问题还高

原因是命中词全是单字（三/分/习、色、一/写/用）， 字面重合但语义完全无关。

最终结论

分数本身没有"覆盖判定"的排序语义，不能靠调阈值解决。 无论阈值调到多少，都会同时存在误判和漏判。

覆盖判定：实词命中率（核心）

把"覆盖判定"和"分数"彻底解耦：不看分数多高，看查询的实词有多少真的出现在课本片段里。

第一步：提取实词

content_words(query) -> set[str]

# 中文：取 bigram（相邻两字），不用单字
#   "光合作用" → {"光合", "合作", "作用"}
#   单字会把「三/分/色」这种偶然重合算成命中，必须用 bigram

# bigram 内任一字是虚词/疑问词/指示词 → 整段丢弃
#   什么 / 怎么 / 哪里 / 的 / 是 / 这 / 我 / 第 ...

# 双字套话整段剔除
#   如何 / 一个 / 应该 ...

# 英文：取长度 ≥2 且非功能词
# 数字：只认章节号 4.1 / 4.1.2 与 ≥3 位年份

第二步：算命中率

hit_ratio = |实词 ∩ Top-3 切片并集| / |实词|

if hit_ratio < GRADER_CONTENT_HIT_MIN_RATIO (0.45):
    → NO_MATCH    # 与 top_score 完全无关

为什么门槛取 0.45

这是实测标定出来的，不是拍脑袋：

样本实词命中率范围
18 条完全无关问题最高 0.40（「矩阵特征值的几何意义」命中「特征」「意义」两个词面巧合）
16 条相关问题最低 0.50
门槛0.45（落在中间，两侧各留 0.05）

实测效果：误判率 0/18，漏判率 0/16。

已知局限：0.40 与 0.50 之间的空档只有 0.10。 这是纯词法方法的下限。要更稳只能上真正的分词器或语义模型，但那会引入外部依赖， 与"零依赖开箱即跑"的约束冲突。

配套补丁：裸数字不算"点名章节"

加了这个门槛后暴露出一个新问题：

extract_section_code("帮我写 3 首关于春天的诗") → "3"

// 只要第 3 章的某个切片排第一，就会以「用户点名了课本的一节」为由
// 判成 SYLLABUS_MATCH —— 实测假阳性，得分 0.5235

修法：裸数字不再算章节引用，必须带上下文（4.1、Bab 4、第五章）。 同时补上汉字章号识别，否则「第五章讲了什么」这种问法会被新门槛误判成 NO_MATCH—— 新增门槛带来的漏判必须同时补掉，否则就是拆东墙补西墙。

三态判定规则

综合分数与实词命中率，输出三态：

状态判定条件（按优先级）回答结构
NO_MATCH 无任何候选切片 明确"课本未覆盖"
citations = []
正文不出现任何页码
retrieval.chunks = []
实词命中率 < 0.45
SYLLABUS_MATCH ① 显式章节锚定且 top1 落在该节
② 或 top_score ≥ 0.55 且实词命中率达标		 严格课本 + 逐条页码
PARTIAL_OR_BEYOND 实词命中率达标但 top_score < 0.55 课本基准 + 深度拓展双层

为什么需要"显式章节锚定"这条特殊规则

学生说「学习 4.1」时，这句话和课本正文几乎没有词面重叠——课本里不会写"学习4.1"这几个字。 纯按语义匹配会落到 NO_MATCH，然后答「课本未覆盖」。

这恰好把产品最重要的演示场景打死了。所以加了一条规则：

if 显式章节号命中 AND 该节有切片 AND top1 落在该节:
    → SYLLABUS_MATCH

依据是"用户点名了课本中确实存在的一节"这个元数据证据，不是语义相似度。 引用页码仍取自真实切片，不会编造。

形态路由

判定该出 PPT / 2D / 3D。规则可解释、可测试：

信号路由结果
用户显式指定（"用 3D"）100% 遵循用户，不做判断
空间类词（结构 / 布局 / 相对位置 / 内部 / 剖面）scene_3d
过程类词（如何演变 / 逐步 / 路线 / 推移 / 受力过程）anim_2d
离散有序词（影响 / 原因 / 条件 / 对比 / 区别 / 时间顺序）ppt
无明确信号默认 ppt（最通用）

每次路由都产出一句人话理由，直接展示给用户：

"问句命中「影响」，属于离散有序、需要逐条阅读的信息 → PPT 课件"

理由不是装饰——它是用户判断"这个形态对不对"的依据。如果理由不合理，用户会说"用 3D"，系统立刻改。

路由准确率的验收是 10 条预置问句 ≥ 80%，实测 10/10。 但只在路由这一层验，不做端到端——因为端到端会把"路由准确"和"检索覆盖"混在一起： 问句在历史教材里必然 NO_MATCH 时，artifact_type 会被置为 none， 于是路由判对也算错。

换教材怎么重标阈值

当前的 0.45 是在一份 KSSM 历史教材上标定的。换语言或换学科必须重标。

  1. 准备两组样本

    15~20 条完全无关的问题（问天气、编程、做饭都行）， 15~20 条确实相关的问题（用新教材里的实词构造）。

  2. 跑出两组的命中率分布

    写个临时脚本调 retriever.grade()，打印每条的 hit_ratio 和 top_score。

  3. 找两条分布的空档

    取无关组最大值与相关组最小值的中间值作为新门槛。

  4. 留出集验证

    另留 10 条没参与调参的样本做验证。只用调参那批测，等于自欺欺人。

  5. 改配置并跑全量测试

    改 .env 的 GRADER_CONTENT_HIT_MIN_RATIO，跑 pytest tests -q 确认没回归。

不要只把阈值调到"测试变绿"。要同时看误判率和漏判率。 全判 NO_MATCH 也能让无关问题测试全绿，但产品就废了—— 所以测试里必须成对出现"无关问题必须拒"和"相关问题必须收"两组用例。

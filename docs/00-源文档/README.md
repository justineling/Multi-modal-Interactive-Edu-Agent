# 00-源文档

> 这里是项目的**原始文档**（Markdown 源文件 + Mermaid 图源），不是给最终读者看的成品。
> 面向读者的版本在 `docs/01-*` ~ `docs/06-*` 的 HTML 文档站里。

---

## 为什么单独放一个目录

这些文件原先散落在 `docs/` 根目录，和 `index.html`、`01-快速开始/` 等并列，看起来像
"又一批文档"，实际它们是**文档站的原料**：

```
源文档（本目录）              文档站（给不同读者看的重组版本）
─────────────────────────────────────────────────────────
SPEC.md          ┐
PRD.md           ├─→  docs/06-项目档案/1. 需求与验收标准.html
ARCHITECTURE.md  ├─→  docs/03-架构设计/（5 篇）
IMPL-NOTES.md    ├─→  docs/06-项目档案/2. 踩坑与裁定.html
QA-REPORT-backend.md ─→ docs/06-项目档案/1. 需求与验收标准.html
```

**区别在于**：源文档是**线性记录**（按时间/章节写下来，有重复、有勘误、有"此处已推翻"），
文档站是**按读者重组**（同一个知识点，给使用者看是一种讲法，给维护者看是另一种）。

两者都要留：源文档保留"当时为什么这么定"的原始语境，文档站负责"现在该怎么用"。

## 每个文件是什么

### SPEC.md — 需求方原始规范

**最高优先级。** 需求方提供，**不可篡改**。`PRD.md` 和 `ARCHITECTURE.md` 都是它的展开。

冲突时的优先级：**`SPEC.md` > `IMPL-NOTES.md` > `ARCHITECTURE.md`**
（后者是设计意图，前者是落地事实）。

> 什么时候看：怀疑"这个需求是不是被理解偏了"的时候。

### PRD.md — 产品需求文档

12 条 P0 需求（P0-01 ~ P0-12），每条都带**可测试的验收标准**。是"做完没有"的判定依据。

> 什么时候看：想知道"这个功能到底要求到什么程度"、验收时对标准的时候。

### ARCHITECTURE.md — 系统架构设计与任务分解

技术选型、模块划分、数据模型、接口契约、任务依赖图。含两张图的**文字描述版**
（完整图在下面的 `.mermaid` 文件里）。

> 什么时候看：要改架构、加模块、理解"为什么这么分层"的时候。

### IMPL-NOTES.md — 实施期踩坑与裁定（★ 最该先读）

按编号记录（E1、E2…E12）每一次踩坑、每一个设计裁定、每一次"原方案被推翻"。

**它记的是「为什么这么写」，比「写了什么」更能防止你把已经修好的 bug 改回去。**

典型条目：
- **E11**：真实 LLM 路径首次验证暴露的两个 P0（提示词缺 JSON Schema、模型档位错配）
- **E12**：换轻量档 + 正文/产物并行、页码钳制、`CancelledError` 是 `BaseException`

> 什么时候看：**改任何代码之前。** 尤其改 `agent_engine.py` / `retriever.py` / `patch_engine.py`。

### QA-REPORT-backend.md — 后端验收报告

P0-01 ~ P0-12 逐条验收结论、8 个缺陷的复现与修复、遗留风险 R1~R8、路由判定。

> 什么时候看：想知道"哪些验过了、哪些没验、有哪些已知空白"的时候。

### class-diagram.mermaid / sequence-diagram.mermaid

`ARCHITECTURE.md` 的两张配图源文件：
- **class-diagram**：数据模型与模块的类图（7 张表、AST 契约、服务层接口）
- **sequence-diagram**：一次提问的时序图（含降级链路 C：三次校验失败 → 降级 mock）

`.mermaid` 是纯文本图定义，用 VS Code 的 Mermaid 插件或 https://mermaid.live 打开可渲染。

> 什么时候看：`ARCHITECTURE.md` 的文字描述不够直观时。

| 文件 | 一句话 | 什么时候看 |

## 与 `increments/` 的区别

`docs/increments/` 是**增量迭代的过程记录**（每个 P1/P2 任务的 PRD、设计、实测数据、
QA 报告），本目录是**项目级基线文档**。

| | `00-源文档/` | `increments/` |
|---|---|---|
| 性质 | 项目基线，长期有效 | 单次迭代的过程记录 |
| 更新 | 改了就改（保留勘误） | 只增不改（历史快照） |
| 例子 | PRD 的 12 条 P0 | P1-03 的延迟优化 PRD/设计/实测 |

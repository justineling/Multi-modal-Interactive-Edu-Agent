三种部署形态、数据库切换、SSE 的反向代理坑、以及成本估算。个人试用和商用上线差别很大，别一上来就搞集群。

三种部署形态

形态适用场景成本限制
本地直跑 个人开发、内测、演示 0 只有本机能访问
单机 Docker 小规模商用（< 500 活跃用户） $12~20 / 月 单点故障，无水平扩展
分离部署 规模化（1000+ 用户） $250+ / 月 运维复杂度上升

建议：先用单机 Docker 跑通，等真的撑不住了再拆。 这个系统的瓶颈在 LLM API 调用，不在服务器性能。 500 个活跃学生同时提问，一台 4 核 8G 也扛得住——因为真正的计算在模型服务商那边。

Docker Compose 单机部署

后端 Dockerfile

# backend/Dockerfile
FROM python:3.13-slim

WORKDIR /app

# PyMuPDF 需要这些系统库
RUN apt-get update && apt-get install -y --no-install-recommends \
    libgl1 libglib2.0-0 && rm -rf /var/lib/apt/lists/*

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY app ./app
COPY scripts ./scripts

# 数据目录挂载出来，容器重启不丢数据
VOLUME ["/app/data"]

EXPOSE 8000
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]

前端 Dockerfile

# frontend/Dockerfile
FROM node:22-slim AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80

docker-compose.yml

services:
  backend:
    build: ./backend
    environment:
      DATABASE_URL: sqlite+aiosqlite:///./data/app.db
      LLM_BASE_URL: ${LLM_BASE_URL}
      LLM_API_KEY: ${LLM_API_KEY}
      LLM_MODEL_ROUTER: gpt-4o-mini
      LLM_MODEL_GENERATOR: gpt-4o
      CORS_ORIGINS: https://your-domain.com
    volumes:
      - ./data:/app/data
    restart: unless-stopped

  frontend:
    build: ./frontend
    ports:
      - "80:80"
    depends_on:
      - backend
    restart: unless-stopped

volumes 那一行不能省。不挂载的话，容器重建后 app.db 和上传的 PDF 全丢——学生所有学习记录都没了。

切换到 PostgreSQL

SQLite 在并发写入时会锁库（500 用户同时提问可能报 database is locked）。 到这一步就该换 PG 了。

步骤

  1. 装 PG 依赖 
    pip install -r requirements-postgres.txt

    包含 asyncpg 和 pgvector。注意这两个包在 Windows 上可能需要编译工具，Linux 上直接装。

  2. 启动 PG 并建库 
    docker run -d --name edu-pg \
  -e POSTGRES_PASSWORD=yourpass \
  -e POSTGRES_DB=edu \
  -p 5432:5432 \
  pgvector/pgvector:pg16
  3. 改 DATABASE_URL 
    DATABASE_URL=postgresql+asyncpg://postgres:yourpass@localhost:5432/edu
  4. 启动，自动建表

    服务启动时会自动 CREATE TABLE。代码一行都不用改—— 双模式通过 EmbeddingStore 协议隔离了。

迁移已有数据？当前没有内置迁移脚本。如果要从 SQLite 迁到 PG， 最简单的方式是重新上传教材（索引会重建），会话历史如果重要需要自己写导出脚本。

PG 模式下的一个注意事项

当前实现把向量存在 Text 列（JSON 数组），检索在 Python 侧算余弦。 即使切了 PG 也不会用上 pgvector 的索引加速。这是刻意的取舍—— 换取"业务代码完全不感知数据库类型"。

如果将来 chunk 量级上到十万级，需要改成真正的 vector(1536) 列 + IVFFlat 索引。 那需要改 db/models.py 和 PgVectorStore，属于较大改动。

反向代理：SSE 的三个坑

SSE 走 HTTP 长连接，nginx 默认配置会把它搞坏。三处必须改：

location /api/ {
    proxy_pass http://backend:8000;

    # ① 必须用 HTTP/1.1，否则 chunked 传输被降级
    proxy_http_version 1.1;

    # ② 关闭缓冲，否则事件被攒成一整块才下发，TTFT 直接失效
    proxy_buffering off;
    proxy_cache off;

    # ③ 延长超时，否则长对话被 60 秒掐断
    proxy_read_timeout 300s;
    proxy_send_timeout 300s;

    # 让 Connection 头透传（有些版本需要）
    proxy_set_header Connection "";
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}

proxy_buffering off 是最容易漏的一条。 不开的话，用户会看到"转圈很久 → 突然一次性出现全部文字"， 流式体验完全消失。而后端日志显示 TTFT 只有 7ms，让你误以为是前端问题。

后端已经在响应头里带了 X-Accel-Buffering: no， 但有些 nginx 配置会忽略它，所以显式关掉更保险。

Cloudflare 用户的额外注意

Cloudflare 免费版会缓冲响应。需要在 Transform Rules 里对 /api/chat/stream 关掉 Cache 和 Buffer，或者该路径不走 CDN 直接回源。

成本估算

基础设施

规模配置月费
MVP 内测（1~50 人）1 台 4核8G + 50G 磁盘$12
小型商用（500 活跃）8核16G + 托管 PG + 对象存储$55
规模化（5000 活跃）前后端分离 + PG 读写分离 + Redis$240

API 成本（这是主要开销）

单学生学完一节（上传 2 本教材 + 学 1 节 + 生成 PPT + 1 个动画 + 6 轮追问）：

项目消耗成本
PDF 向量化（一次性）35 万 tokens$0.007
生成 + 6 轮追问4 万输入 + 1 万输出$0.015~0.030
单节合计—$0.02 左右

三个降本手段：

  1. 模型分层路由：路由/评估用 mini 级模型，只有 JSON 生成用大模型。能省 70% 以上。
  2. 前缀缓存：把章节原文和 JSON Schema 固定在 System Prompt 头部。 多轮追问时 90% 的输入命中缓存，成本降到 1/10。
  3. 本地 embedding：默认就是本地确定性实现，向量化成本为 0。

安全清单

#项做法
1API Key 不进代码只放 .env 或环境变量；.env 在 .gitignore 里
2CORS 白名单生产环境把 CORS_ORIGINS 改成真实域名，不要留 *
3上传体积限制MAX_UPLOAD_MB 与 MAX_PDF_PAGES 都设上，防 DoS
4注入防护已内置：AST 基类递归扫描 HTML/JS 标记，命中即拒绝
5无代码执行架构上不存在"LLM 生成代码并执行"的路径，这是最大的安全优势
6数据备份定期备份 data/ 目录（db + uploads）
7登录体系当前没有。公网部署前必须加一层（nginx basic auth 或自建认证）

当前版本是单用户设计，没有登录、没有租户隔离。 直接暴露到公网等于任何人都能用你的 API Key 烧钱。上线前至少加一层认证。

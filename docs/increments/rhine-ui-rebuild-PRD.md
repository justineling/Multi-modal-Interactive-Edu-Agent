## 0. 项目信息与产品定义

### 0.1 原始需求复述

> 「我希望使用 `@skill:rhine-lab-ui` 这个 ui skill 对当前的 ui 进行重构（备注：不仅是 ui 改色而已，而是从布局，思想上，彻底的 ui 重构）」

关键词是**「不仅是改色」「布局、思想上」「彻底」**。判定：这不是换皮（换 token / 圆角 / 焦点），而是**信息架构重建**——把「聊天框 + 画布」这一产品心智重新定义为别的什么东西，并让布局、编号、状态、分隔手段跟着这个新心智一起重排。

### 0.4 User Stories

1. 作为**自学的学生**，我希望打开工作区就看到「当前在调阅哪一本教材的哪一页、这一页出自教材第几页」，以便我随时能翻书核对、不用回想刚才聊到哪了。
2. 作为**自学的学生**，我希望在画布上点中一个元素追问时，界面明确显示「这是对 `FILE X-003` 第 `01/05` 页的第 `T-004` 次定点修订」，以便我确信系统只改了那一处、其余页没被动过。
3. 作为**用户本人（演示者）**，我希望「演示模式 / mock 数据」的状态无需任何操作就常驻且醒目，以便演示现场不会把确定性 mock 误当成真实模型输出。
4. 作为**用户本人（测试组织者）**，我希望重构能与 6 项真人测试并行、旧界面仍可对照，以便我能分清「学生看不懂内容」和「学生看不懂新外壳」。
5. 作为**键盘 / 读屏用户**，我希望所有调阅、跳页、追问、切换都能键盘到达且有无障碍名称，以便档案终端不是一张只能看的图。

## 1. 设计契约（四行）

```
depth:        complex
证据:         depth-levels.md §3「complex = 系统级重建：多操作区 + 3–4 个纸面系统 + 全组件覆盖 + 双动效族」；
              layout.md §1 三层骨架 / §三栏 / §对齐纪律；patterns.md §1 细线组织 + §4 编号系统 + §6 刻度轨 + §7 呼吸点
主屏任务:      在三秒内定位并调阅「DOC-001 的 FILE X-003 第 01/05 页」，并可携带锚点发起一次带编号的 T-xxx 定点修订
不做什么:      不做逐帧入场序列 / 启动屏；不加第二个强调色；不编造任何无数据源的遥测；
              (B) 产物内容层只做装裱层衔接、不改 PALETTE 与 6 种布局语义色（Q-1 已拍板 2026-11-07）；
              不改后端 AST 契约、不改 LLM 提示词颜色枚举、不改三个确定性渲染器（第 4.6 节）
```

### 1.1 为什么是 `complex` 而不是 `maximal` / `moderate`

| 档位 | 判定 | 理由 |
|---|---|---|
| `moderate`（默认档） | **否** | `depth-levels.md` §2 定义 moderate 为「重构外壳 + 加两个核心模式（kicker / meta）+ 细线 + 编号，覆盖共享控件」，且明确「**内容仍主导构图**」「不要做启动序列、不要做多区域仪表盘、不要加三维」。用户原话「不仅是改色」「布局、思想上」「彻底」要求的是**信息架构反转**（画布从「预览」升为「被调阅的卷宗页」），moderate 不重排 IA，做不到。skill 也规定「用户明确说了档位（完整重构）→ 照办」。 |
| `complex` | **是** | 用户说「彻底」= `depth-levels.md` §3 的「**读起来像一个被重建过的系统，不是套了皮**」。本产品天然具备 complex 的四个特征：① 多个操作区（目录树 / 调阅流水 / 卷宗页 / 检视与状态）；② 3–4 个协同纸面系统（细线网格、方向性刻度、超大编号 `01/05`、`.rl-meta` 元信息对）；③ 全组件覆盖（对话流、树、引用、输入、锚点、工具条、版本、状态、焦点、选中、滚动）；④ 两个动效族（揭示/加载 + `.rl-status--live` 状态循环）且需减少动效等价实现。complex 的典型场景就是「档案终端」。 |
| `maximal` | **否** | `depth-levels.md` §4 要求「逐帧校准的入场序列 / 启动屏 / 状态驱动仪表 / 定制构图」，典型场景是「旗舰展示、启动序列、活动微站」。本项目是**学生长时间使用的学习工具**：每次进入放启动序列会直接损害「三秒定位并调阅档案」的主屏任务；且 maximal 易诱发「为填满空间编造遥测」，而 complex §3「不该做」明令禁止编造遥测，本 PRD 第 2.3 节也把「不编造」写成硬约束。 |

> 依据 `depth-levels.md`「深度不是借口」：升档**不**允许编造假编码、重复指标、加第二强调色、缩小必要文字、削弱可访问性。所有档位都必须过审计、保留对比度、键盘可达、减少动效。

## 2. 新的信息架构（本 PRD 的核心）

### 2.1 心智反转：从「聊天框 + 画布」到「档案调阅终端」

| | 旧心智 | 新心智 |
|---|---|---|
| 产品是什么 | AI 聊天工具 + 一个预览窗 | **一份可被逐条调阅、逐处批注、逐版修订的档案卷宗** |
| 用户在做什么 | 「看 AI 刚回了什么」 | 「就某份已归档教材的某一页，发起一次带编号的调阅 / 修订请求」 |
| 对话流 | 聊天历史 | 卷宗的**调阅 / 修订流水**（`T-xxx`） |
| 画布 | 产物预览 | 卷宗**当前打开的那一页**（`FILE X-xxx` / `01/05`）——**主内容** |
| 目录树 | 侧边功能 | 卷宗**索引**（`DOC-xxx` / 章节 code / `p.xx`） |
| 引用 | 气泡里的脚注 | 卷宗**出处**（`[p.94]`，可回溯教材） |
| 锚点追问 | 一个便捷功能 | 对某一页 / 某一元素的**定点批注**（`PATCH A-xx`，只改那一处） |
| 版本历史 | 一个下拉菜单 | 卷宗**修订记录**（`REV-xx`） |

**这是「思想」层面重建的判据**：编号不再是装饰，而是**真实对象的主键**。`depth-levels.md` §3 要求「每个常驻仪表都要有真实的分组、方向、状态或世界观职责」，并明令「不要为了填满空间而编造遥测、重复指标、增加颜色」；`SKILL.md` 味道命门也要求 `.rl-kicker` 显示真实元信息。因此本 PRD 拒绝 `ACCESS LEVEL 04`、`CHANNEL 07`、`LOAD 42%`、`SYS/NOMINAL` 这类**在本产品没有对应真实对象**的伪档案词——「无编号 = 未归档」成立，但「编出来的编号 = 假档案」，比不编号更糟。

**布局反转的说明（为什么这是「布局思想」而非调比例）**：现有 `SplitWorkspace.tsx` 是「左聊天 42% + 右画布 58%」，聊天主导、画布是「预览」。重构后画布成为 `<main>` 的 `1fr` **主内容栏**，对话与输入退到 `320px` 检视栏——因为在这个产品里，用户 / 学生真正要读的是**那一页产物**，对话只是产生它的调阅流水。`layout.md` §1 的双栏原型是「左三维主视觉、右档案文本」，本项目把「主视觉」对应为卷宗页、`1fr`，把「档案文本」对应为索引 / 流水 / 元信息，是同一关系的抽象，而不是随意三等分。

**对齐纪律**（`layout.md` §对齐纪律）：
- 所有元素只对齐**两条线**：左线 `--rl-gutter: 59px`、右线 `viewport - gutter`。品牌块、目录树、页签、流水行、底部刻度全部左对齐同一条线；编号 / 页码 / 版本 / 时间全部右对齐同一条线。
- **不允许第三个对齐位置**（卡片内缩 24px 会让「档案纸」感散掉）；居中只允许出现在模态框内。
- 分栏靠 **72px 留白**（`--rl-space-8`），**不画 1px 竖线**；竖线仅两个合法例外：`patterns.md` §1 的目录树缩进脊线（每层各一条）、`.rl-ticks` 单根刻度竖线。
- `rl-shell` **只接受 3 个直接子元素**（`layout.md` §「只接受三个直接子元素」）：第 4 个会创建隐式行、`1fr` 落到错误元素、页面高度塌陷。故品牌块 + kicker + 面包屑必须包进同一个 `<header>`。
- 响应式（`layout.md` §响应式断点）：`>900px` 三栏 / gutter 59px；`≤900px` 单栏堆叠 / gutter 24px / h1 44→32、h2 32→26；`≤560px` gutter 18px / h1→26 / 页签横向滚动 / 底部纵向堆叠。**窄屏不等比缩小正文**：正文保持 15px、输入 16px、触控 44px。此断点顺带缓解已知问题 D-10「窄屏布局未优化」。
- 栏宽 `220 / 1fr / 320px` 为 `layout.md` 三栏的**建议值**，320px 检视栏能否容纳 Composer（`LAYOUT.composerMinHeight: 96`）与 16:9 画布的实际观感需架构师复核 → **Q-6**（不擅自定死；原型阶段不展开）。

### 2.8 状态区与刻度轨对应什么真实进度

**`.rl-status--live` 呼吸点**（`patterns.md` §7：全系统唯一允许的循环动画，2.4s 周期、只动透明度、一屏最多一个、`prefers-reduced-motion` 下停止）：
- **只表达「SSE 流式生成中」**：从 `beginStreaming`（置 `streamingMessageId`）→ `turn_start` → token / `citations` → `turn_end` 期间为 live，状态词 `GENERATING`。
- 流结束后**立即转为静态墨色实心点**（`.rl-status`，去掉 `--live`），状态词 `IDLE` / `TURN COMPLETE` / `NO MATCH` / `PATCH APPLIED`。
- 不用于「在线 / 健康」这类常亮状态（会退化为装饰性循环动画）；不与「演示模式」共用呼吸点。

**`.rl-ticks` 刻度轨**（`patterns.md` §6：视觉 1px 竖线、热区 **44px**、当前项 9px→18px 转墨色、220ms、`aria-current="true"`）：
- **对应当前幻灯片序号 `01/05`**：每一根 tick = 一页，当前页拉长转墨色，右侧配等宽 `01/05`。点击可跳页（若现有能力支持）。
- **不映射**「检索进度 %」「生成进度条」：SSE 是离散事件序列，没有连续真实值；硬做就是编造遥测。
- 2D / 3D 形态下没有「页」的概念，刻度轨应改映射**时间轴关键帧序号**或**场景实体编号**（都来自真实 AST），但具体由谁定、如何与 `A-xx` 锚点编号对齐 → **Q-3**（不擅自填；原型阶段不展开）。

**暖杏金两处预算**（`SKILL.md` 铁律 1 + 味道命门）：一屏最多两处，分配为 ① 演示模式黄标的琥珀细线（第 5 节）② `.rl-status--live` 呼吸点。当前页 tick 用**墨色**（`patterns.md` §6 当前项转 `--rl-ink`），不占琥珀额度；形态切换 / 选中 / 悬停一律用墨色或细线。演示模式与流式生成同时出现时恰好用满两处，不超限。

| 契约 / 工期 | **改 B = 同时改四处**：`AST schema`（`Entity2D.color` / `Node3D.color`）、后端 Pydantic validators、LLM 提示词里的颜色枚举、Konva / Three 确定性渲染器。直接触碰「LLM 只填 JSON、前端确定性渲染、零编译、100% 不崩」的核心原则；已生成的历史版本产物 / 旧数据颜色会失配。工期与回归面在三个方案中最大 |
| 收益 | 整屏视觉语言统一，「彻底」程度最高 |

### 取舍对照（决策依据，完整保留）

| | 方案 1：只重构 A | 方案 2：A+B 都重构 |

| 学生读得懂课件 | 保持现状，无风险 | 语义色丢失、字阶重做、打印观感变化，需重新验证 |

## 4. 装裱层语法规格（Q-1 已拍板的正式范围）

> 本节是 **Q-1 拍板后的正式实现范围**，取代 v1.0 中「中间态」那一句话。Q-2 拍板的单页原型按本节实现。

**六条规格索引**（实现与验收逐条对照）：

原型阶段的两个非阻塞 Q 处置见 4.8（Q-4 审计豁免目录）与 4.9（Q-5 默认亮 / 暗）。

### 4.1 范围声明

| 层 | 本次是否改动 | 具体内容 |
|---|---|---|
| **L1 · A 层外壳** | **是（全量）** | 品牌块、kicker、三栏骨架、索引 / 流水 / 检视、输入、工具栏、版本、状态、错误、PWA、演示黄标；`index.css` 与 `theme.ts` 中的 A 层常量 |
| **L2 · 装裱层（本节）** | **是（新增）** | 卷宗页页框、框外页眉页脚、出处脚注、框外标签字阶；全部落在外壳 / 容器组件内 |
| **L3 · B 层产物画面** | **否** | `PALETTE`、6 种 `layouts/*` 画面、2D / 3D 画面、语义色、标题字阶、图形元素、导出 PDF 打印结果 |

**判据**：改动若落在 `SlideRenderer` / `Anim2DRenderer` / `Scene3DRenderer` / `layouts/*` 文件内，即越界；装裱层改动应只落在外壳 / 页框容器组件与其样式中。

### 4.2 规格 1 · 卷宗页页框

| 项 | 规格 |
|---|---|
| 线 | **1px `var(--rl-line)`（`#aaa59a`）细线**；四边闭合或按需只画必要边；线的三级体系见 `patterns.md` §1（主 `--rl-line` / 次 `--rl-line-soft` / 72px 短黑线是「块」不是线） |
| 形状 | **`border-radius: 0` 直角**（`SKILL.md` 铁律 2；审计 error 项） |
| 层级 | **无 `box-shadow`**；`--rl-overlay-shadow` 只给模态 / 菜单 / 抽屉等真浮层（铁律 2；审计 error 项「无非浮层 box-shadow」） |
| 类名 | 用 `.rl-panel`（`quickref.md` §容器「细边框面板」），不自造 `.rl-card` 等不存在的类名 |
| **归属** | **页框是 A 层，不是 B 层卡片**。它承载「这是一份被归档的卷宗页」的语义，不承载课件内容的分组；因此不得用「卡片网格 + gap + 圆角卡片」去组织 6 种布局（`layout.md` §常见布局错误「档案是行不是卡」） |
| 与画面的边界 | 页框与课件画面之间用**留白**（建议 `--rl-space-4` 16px 内衬）+ 1px 线分隔；**不用灰底、不用投影、不叠加半透明遮罩** |
| 打印 | 页框不得破坏导出 PDF 的 6 页 / 16:9 / 纯矢量与分页（第 8 节 AC-R5） |

### 4.3 规格 2 · 页眉 / 页脚（四类编号在页框之外）

四类编号全部落在**页框之外**——页框上方为页眉、下方为页脚，与课件画面之间有明确的 1px 线边界：

| 编号 | 位置 | 形态 | 对齐 |
|---|---|---|---|
| `FILE X-003` | 页眉左 | `.rl-label`（10px 大写 1.4px 字距） | 左线 `--rl-gutter` |
| `DOC-001` | 页眉右 | `.rl-label` | **右线** `viewport - gutter` |
| `[p.94]` | 页脚左 / 出处脚注 | `.rl-meta` `SOURCE / [p.94]` | 左线 |
| `01/05` | 页脚右 | `.rl-readout` 或 `.rl-meta dd`，`tabular-nums` | **右线** |

- 页眉与页框之间一条 `.rl-rule--soft`，页脚与页框之间一条 `.rl-rule`；**编号不叠加、不浮在课件画面上**（不侵入 B 层）。
- 全部编号 `font-variant-numeric: tabular-nums`（`patterns.md` §4，避免翻页时横向抖动）。
- 只对齐左线 / 右线两条线（`layout.md` §对齐纪律），**不允许第三个对齐位置**；页眉页脚本身不居中。
- 编号取真实数据：`FILE X-003` ← artifact id、`01/05` ← `SlideRenderer` 当前页 / 总页、`[p.94]` ← 重绑定后的真实切片页码、`DOC-001` ← `document_id`。**只搬位置，不改数值**。

### 4.4 规格 3 · 出处脚注

- 引用页码 `[p.94]` 用 `.rl-meta`（`SOURCE / [p.94]`、`SECTION / 4.1.3`、`DOC / DOC-001`）或 `.rl-rule--short`（72px 墨色短黑线，作段落签名）与页框衔接，**不侵入画面**。
- `.rl-rule--short` **一段仅一条**（`SKILL.md` 味道命门规则 3），不得变成装饰花纹；线的用法遵守 `patterns.md` §1 三级体系。
- 脚注与画面的边界靠 **1px 线 + 留白**，不靠背景色块 / 卡片描边（铁律 4）。
- **保留行为契约**：`[p.94]` 是后置确定性重绑定后的真实页码；检索不到时显示「课本未覆盖」，**禁止编造页码**；装裱层只改变呈现位置与形态，不改数字、不改引用链路。

### 4.5 规格 4 · 字阶微调的边界

| | 允许 | 禁止 |
|---|---|---|
| 对象 | 页眉页脚、页框**外**的标签（`.rl-label` / `.rl-kicker` / `.rl-meta` / `.rl-readout`） | 课件**内页**的标题字阶、字号、配色、字体、行高、图形元素 |
| 手段 | 字号 / 字重 / 字距，使其符合 `patterns.md` §3 字阶对比：标签 ≤12px + 大写 + ≥1px 字距；正文 15px；字重只用 300/400/600/700/750，**无 500** | 改 `SlideRenderer` / `Anim2DRenderer` / `Scene3DRenderer` / `layouts/*` 内任何排版属性 |
| 目的 | 让「档案纸」与「课件页」在**框外**的字号层级上不打架 | 把课件改灰 / 改小 / 改细线化 |

> **越界判据**：`git diff` 若触及 L3 文件，即视为违反 Q-1 拍板范围。
> **注意**：v1.0 §5「特别处理 ③」原第 3 条曾写「若需调整标题层级，走字阶差」——那是 Q-1 未拍板时的候选写法，**已由本条取代并收严**：课件内页标题层级一律不调整。

### 4.7 规格 6 · 视觉依据与交付说明措辞

**为什么「档案外壳 + 彩色课件内页」不构成违和**：

真实纸质档案卷宗里**夹有彩色插图、图表、照片、折页**是常态。档案的「暖灰纸 / 细线 / 编号 / 元信息」属于**装帧与检索系统**，彩色页面属于**被归档的原件内容**——二者本来就分属不同层级，不是同一张皮上的两种风格。`layout.md` §1 也写明 RhineLabUI 原设计的桌面构图是「**左三维模型、右档案文本**」的并置，主视觉并未被要求变成米色；本方案把「彩色课件页」对应为那个主视觉、「档案外壳」对应为档案文本，是同一关系的抽象。

因此：**装裱层的任务是把彩色课件装进档案页框，不是把彩色课件染成档案色。** 统一感来自**同一根 1px 细线、同一套编号、同一条对齐线**，而不是同一套颜色。

**可用于交付说明的一句话措辞**（原型与全量交付均可直接引用）：

> 「档案外壳负责『这是第几份、第几页、出自哪里』，彩色课件页负责『这一页教什么』；如同纸质卷宗里夹着一页彩色插图，装帧语言与原件内容各司其职，不互相染色。」

**禁止使用的措辞**：不得写「贴了两张皮」「双主题」「风格不统一」「待修复的违规」；不得把彩色内页描述为需要整改的对象。交付说明还必须同时写明三项降级 / 合规事实：**字体已降级**（MiSans 未打包，AC-V12）、**三行品牌块是排版不是官方 logo**（AC-V13）、**B 层彩色受后端 AST 契约约束且经 Q-1 拍板保留**（本节 4.6）。

### 特别处理 ① 演示模式黄标：不违反「一屏一个墨块 / 语义色不用」

- **冲突点**：现有黄标是亮黄色块（`PALETTE[2] #F59E0B` 系）——既是第二个强调色，又可能构成第二个墨块 / 灰底分区，还带圆角。skill 铁律 1 禁第二强调色与语义色、铁律 6 一屏一个墨块、铁律 2 无圆角无投影。
- **处理**：**不新增任何颜色**。暖杏金 `--rl-accent #9b7247` 本身就是琥珀系，是全系统唯一允许的信号色。把「亮黄填充块」改为 **墨色加粗大写文字 `DEMO MODE / MOCK OUTPUT` + 一条 1px 琥珀细线（或琥珀左竖线，可复用 `.rl-cell--locked` 的语义）+ 墨色实心状态点**，落在 `.rl-kicker` 常驻槽位。

### 特别处理 ② 错误信息（现在是红色横幅）

- **现状**：`useWorkspaceStore.error` 展示；SSE `error` 事件带 `code` / `stage`（`retrieval \| route \| generate \| validate \| patch`）/ `retryable` / `message`；`ErrorBoundary` 负责渲染异常降级为「可读错误 + 重试」。
- **冲突**：`danger: #EF4444` 语义红 + 红色横幅（色块）= 语义色 + 面分隔，违反铁律 1 / 4。`SKILL.md` 禁止模式里已给出范例：「用 `.rl-ink` 加粗 + 一行大写 `RESTRICTED` 说明状态」。
- **处理**：改为 `.rl-note` / `.rl-status` 形态——**墨色加粗大写状态词 + 一行中文说明 + 短黑线或琥珀左竖线**，例如 `RETRIEVAL FAILED · RETRYABLE` / 「检索未命中课本，正在重试…」；`stage` / `code` / `retry` 用 `.rl-meta` KEY/VALUE 呈现。可重试态用琥珀细线 + `RETRYING`；不可重试态用墨色实心点 + `HALTED`。输入校验类错误用 `data-invalid="true"`（`.rl-field` 左侧 3px 琥珀边，`quickref.md` §data 属性），属合法琥珀表达。
- **行为契约必须保留**：`error` **不关流**、之后仍补 `turn_end`、重试态与终态可区分、`ErrorBoundary` 有「重试」入口（`.rl-btn` outline，**不是墨块**）。

## 7. 与当前「测试期」的冲突 · **Q-2（已拍板 2026-11-07）**

### 7.1 事实：项目明确处于测试期

- `NEXT-ACTION.md` 开头：**「当前阶段：测试期，不是开发期」「用户已明确要求：先停止写代码，先做真实测试」「你读到这份文档时，不要主动开始实现新功能」**；并指出项目已连续四轮代码迭代，但**从未用真实教材验证过**，「继续写代码的边际收益已经很低，而『假设错误』的风险很高」。
- `docs/用户任务清单.html`：**A 类 6 项真人测试全部尚未完成**（① 有头浏览器点导出 PDF ② 真实教材跑完整流程 ③ 真实 Key 跑 3~5 轮看内容质量 ④ PWA 装桌面用一整天 ⑤ 真实 GPU 看 3D+2D ⑥ 手机 / iPad 看布局）；另有 B 类 7 个待拍板决策、D 类 11 条已知问题。
- 测试顺序（`NEXT-ACTION` §3）：第 1 步用户自己用真实教材跑一遍 → 第 2 步决定是否重标 grader 阈值 → 第 3 步找 1~2 个真实学生试用 → 第 4 步据反馈定下一步；且「**不要跳过第 1 步直接找人试用**」。用户任务清单结尾：「如果只能做一件事：先做 A 类第 2 条」。
- `NEXT-ACTION` §6 的路线表里**没有任何 UI 重构条目**，甚至有两条明确「不要做」。

### 7.2 冲突本质

一次 `complex` 系统级重建会改掉 `SplitWorkspace.tsx`、`TopBar.tsx`、`index.css`、`theme.ts` 及十余个组件，等于**把尚未经过真人验证的交互基线整体替换**。后果不是「测试要重跑」这么简单，而是 **6 项真人测试的观察对象消失、观察结论无法归因**——分不清「学生看不懂内容」还是「学生看不懂新外壳」；A-2 / A-3 / A-5 / A-6 的判据都要重标。这正好撞上 `NEXT-ACTION` 警告的「假设错误」。

### 7.3 三个推进方式的取舍（决策依据，完整保留）

| 方式 | 做法 | 对测试的影响 | 代价 / 风险 | 工期 |
|---|---|---|---|---|
| **① 直接替换现有 UI** | 全量重构 A（或 A+B），删除旧 UI | **6 项真人测试全部要重来**；已记录的观察基线作废；重构缺陷与原有产品问题混淆，归因失效 | 与「先停止写代码」的明确指令正面冲突；在没真实教材验证前再叠一轮大改，正是 `NEXT-ACTION` 警告的情形 | 最大 |
| **② 可切换的并行皮肤 / 加开关** | 新增一套档案皮肤，旧 UI 保留，运行时或构建期切换 | **旧 UI 继续做对照测试**，6 项测试不中断；还能做 A/B 观感对照 | 需维护两套外壳与两套样式作用域；状态 / 事件绑定双份不能打架；`.rl` 根类作用域与现有 Tailwind 深色主题并存有串味风险；测试矩阵翻倍 | 中~大 |
| **③ 先做单页原型给用户看，确认后再全量铺开** | 只做一个静态 / 半静态原型页（品牌块 + kicker + 三栏骨架 + 一处墨块 + ticks），**不进 `frontend/src`** | **生产 UI 完全不动，测试照常**；用户先对「档案终端」的心智与观感拍板 | 原型 ≠ 可交互产品，可能给人「已经做完了」的错觉；需明确标注「非生产、不可用于测试」 | 最小 |

### 7.4 用户决策与落地约束（2026-11-07）

**决策：采用方式 ③「先做单页原型」，本次不写任何生产代码。**

2环境搭建与运行

从零到看见界面。有一键脚本，也有手动步骤；最后附「装到桌面」的方法和三个必踩的坑。

只想看效果？别往下读。直接双击根目录的 1. 启动网页端(Windows).bat （Mac/Linux 用 2. 启动网页端(Mac-Linux).sh）。脚本会自动装依赖、建配置、生成样本教材、 开两个窗口启动前后端，然后打开浏览器。

最快方式：一键启动

平台文件操作
Windows 1. 启动网页端(Windows).bat 双击
macOS / Linux 2. 启动网页端(Mac-Linux).sh chmod +x "2. 启动网页端(Mac-Linux).sh" && ./"2. 启动网页端(Mac-Linux).sh"

脚本会依次做五件事，首次运行会自动补齐环境：

  1. 检查 Python 与 Node.js

    缺失时给出下载链接和安装提示，不会闷着失败。

  2. 准备后端虚拟环境

    backend/.venv 不存在则创建并 pip install（首次约 1-2 分钟）。

  3. 准备配置文件

    backend/.env 不存在则从 .env.example 复制（默认演示模式）。

  4. 准备前端依赖与样本教材

    node_modules 不存在则 npm install（首次约 1-3 分钟）；样本 PDF 不存在则现场生成。

  5. 启动服务并打开浏览器

    后端和前端各开一个独立窗口，标题分别标注端口。等就绪后自动打开 http://localhost:5173。

停止服务：关闭那两个命令行窗口。窗口标题是「智能助教 · 后端 :8000」和「智能助教 · 前端 :5173」， 关哪个停哪个，日志也各看各的——比把两路日志混在一个窗口里好排查得多。

为什么 Windows 脚本是一个 .bat 加一个 .ps1？ 因为批处理文件的中文编码很坑：存成 UTF-8 会在中文 Windows 上被按 GBK 解析、整行截断、命令错乱； 存成 GBK 又会在英文 Windows 上显示乱码。解法是让 .bat 一个中文字符都不含（纯 ASCII，任何代码页都能正确解析）， 只负责调用 scripts/start-web.ps1；中文提示和全部逻辑放在 .ps1 里， 以 UTF-8 with BOM 保存，PowerShell 能正确读取。

前置要求

工具版本要求检查命令
Python3.12 或更高（推荐 3.13）python --version
Node.js20.19 或更高（推荐 22）node --version
Git任意近版本git --version

不需要安装数据库。默认用 SQLite，第一次启动时会自动在 backend/data/app.db 创建文件。 也不需要 PostgreSQL、Redis、Docker——这些在生产部署时才涉及。

手动启动后端

  1. 进入 backend 目录，创建虚拟环境 
    cd backend

# Windows
python -m venv .venv
.venv\Scripts\activate

# macOS / Linux
python -m venv .venv
source .venv/bin/activate

    虚拟环境的作用：把这个项目的依赖装在一个隔离目录里，不影响你电脑上其他 Python 项目。 激活后命令行前面会出现 (.venv) 字样。

  2. 安装依赖 
    pip install -r requirements.txt

    大约 20 个包，主要是 FastAPI、SQLAlchemy、PyMuPDF。首次安装约 1~2 分钟。

  3. 复制环境变量模板 
    # Windows
copy .env.example .env

# macOS / Linux
cp .env.example .env

    可以先不填任何 Key。留空 LLM_API_KEY 会进入演示模式， 用内置的确定性生成器跑通全链路。界面顶部会有黄色标识提示。想接真实模型再填。

  4. 启动服务 
    uvicorn app.main:app --reload --port 8000

    --reload 表示改代码自动重启（开发时用，生产不要用）。

看到这样的输出就成功了：

INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
INFO:     Application startup complete.

立刻验证一下：浏览器打开 http://127.0.0.1:8000/api/health，应该返回：

{
  "code": "OK",
  "data": {
    "demo_mode": true,
    "app_version": "0.1.0",
    "database_backend": "sqlite+aiosqlite",
    "embedding_mode": "local",
    "vector_store": "MemoryVectorStore",
    "artifact_types": ["ppt", "anim_2d", "scene_3d"]
  }
}

demo_mode: true 说明当前是演示模式（没配 Key），这是正常的。

手动启动前端

新开一个终端窗口（后端那个别关）：

cd frontend
npm install
npm run dev

输出里会有一行：

  ➜  Local:   http://localhost:5173/

必须用 localhost，不要用 127.0.0.1。 Vite 默认绑定 IPv6 的 ::1，用 127.0.0.1:5173 访问会被拒绝连接。 这是本项目最高频的"启动失败"原因。

打开 http://localhost:5173，应该看到左右两栏：左边对话区（顶部是文件区），右边画布区（空态会显示三个示例问句）。

生成样本教材

项目自带一个脚本，能生成一份 113 页的模拟 KSSM 历史教材，用于演示和测试：

cd backend
python scripts/make_sample_pdf.py

输出：

已生成 .../backend/data/sample_textbook.pdf（113 页）

这份样本的章节结构是刻意做复杂的——3 级层级、5 章、15 节、45 小节、65 个目录节点。 这是为了验证解析器真的能识别多层章节号（Chapter 4 → 4.1 → 4.1.2）， 而不是只能处理简单结构。

内容是基于公开历史常识改写的，不涉及真实教材版权。真实教材请自行上传。

装到桌面（PWA）

界面支持安装成桌面应用。装完是一个独立窗口——没有地址栏、没有标签页，看起来和原生软件一样。

怎么装

  1. 启动服务，用 Chrome 或 Edge 打开

    http://localhost:5173

  2. 看地址栏右侧的「安装」图标

    一个显示器带下箭头的图标，或者一个 ⊕ 样式的图标。点它。

  3. 确认安装

    桌面和开始菜单会出现「智能助教」，双击打开就是独立窗口。

看不到安装图标？两个原因：① 用的是 Firefox 或 Safari（不支持桌面 PWA 安装）； ② 访问的是 127.0.0.1 而不是 localhost——PWA 要求安全上下文，这两个在部分浏览器上不等价。

装了之后有什么不一样

项效果
窗口形态独立窗口，无地址栏、无标签页，Alt+Tab 里是一个单独的应用
入口桌面图标 / 开始菜单 / 任务栏固定
启动界面壳被缓存，打开比首次加载快
离线时能看到离线提示页，而不是浏览器的「无法访问此网站」

它不是「真离线」——这点要说清

PWA 只缓存界面壳，不缓存任何数据。Service Worker 里明确排除了所有 /api/ 请求。

这不是偷懒，是必须的：一旦缓存了对话接口 POST /api/chat/stream， 用户会永远拿到第一次的答案，而且这个 bug 是静默的——界面一切正常，只是 AI「不回复新问题」，极难排查。

所以后端必须一直开着。后端停了之后：刷新页面 → 看到离线提示页； 界面壳还能加载（被缓存了），但发消息会失败。

为什么不做成真离线（Tauri）

真离线需要把 Python 后端一起打包。而 PDF 解析依赖 PyMuPDF——换成 JS 的 pdf.js 或 Rust 的 pdf-extract， 章节号识别质量和页码映射精度会明显下降，而那正是「严格按教材」这个卖点的地基。

Tauri + Python sidecar 的体积是 80~150MB，还要维护一套跨平台打包链（PyInstaller 打包 FastAPI、 处理 PyMuPDF 的 DLL、sidecar 生命周期管理、端口动态分配）。

在「用户到底需要桌面感，还是真离线」还没验证之前，PWA 是成本最低的试探：零构建链，半小时的配置，随时可弃。 如果后面确认要真离线（比如学校机房无网），再上 Tauri 也不迟——前端代码可以原样复用。

环境变量说明

全部在 backend/.env 里配置，默认值见 backend/app/config.py：

变量默认值说明
DATABASE_URLsqlite+aiosqlite:///./data/app.db换成 postgresql+asyncpg://... 即切换 PostgreSQL + pgvector
LLM_BASE_URLhttps://api.openai.com/v1任何 OpenAI 兼容端点（DeepSeek、通义、本地 vLLM 都行）
LLM_API_KEY空留空 = 演示模式，全链路仍可跑通
LLM_MODEL_ROUTERgpt-4o-mini轻量任务：正文流式生成、形态路由、相关性评估
LLM_MODEL_ARTIFACTdeepseek-flash产物生成档位（PPT / 2D / 3D 的 JSON AST）。置空则跟随 GENERATOR
LLM_MODEL_GENERATORgpt-4o重档：LLM_MODEL_ARTIFACT 的回退目标，也是将来更复杂任务的落点
GRADER_CONTENT_HIT_MIN_RATIO0.45实词命中率门槛，低于它判「课本未覆盖」。换教材要重标
RETRIEVAL_TOP_K8检索返回的候选切片数
MAX_UPLOAD_MB50上传体积上限
MAX_PDF_PAGES600单份 PDF 页数上限
ARTIFACT_VERSION_KEEP20每个产物保留的历史版本数，超出后旧版本只读不可 patch

产物并行与换档（P1-03）

真实模式下产物生成曾是耗时大头——实测 55.5 秒占整轮 83.7%，其中 36~54 秒是模型「思考」。 改成「换轻量档 + 正文/产物并行」后，整轮 66.3s → 18.13s（P50，n=15）。

变量默认值说明
LLM_MODEL_ARTIFACT_BY_TYPE 空 分形态覆盖档位，格式 anim_2d=deepseek-v4-pro,scene_3d=deepseek-v4-pro。键写错启动即抛 ValueError（不静默忽略）
ARTIFACT_PARALLEL_ENABLED true 正文与产物并行生成。关掉即回到串行（产物耗时 +10.8s，但行为更易排查）
ARTIFACT_FORK_MODE after_first_token 并行的分叉时机。after_first_token 保证 TTFT 不被产物耗时污染；immediate 更早开始但可能抬高 TTFT
ARTIFACT_MAX_CONCURRENCY 8 并行信号量上限。多用户并发时防止瞬间打爆上游配额
ARTIFACT_RATE_LIMIT_RETRY 1 产物阶段遇 429 后的串行重试次数（不是「从头重跑正文」）

换档的代价：契约一次通过率可能下降，而一次重试就是一次完整调用——两次就吃掉全部收益。 所以必须同时看「重试率」，不能只看耗时。

三条回退路径：
① 全局 → LLM_MODEL_ARTIFACT= 置空（跟随 GENERATOR）
② 分形态 → LLM_MODEL_ARTIFACT_BY_TYPE=anim_2d=重档模型（不整份回退，PPT 的收益不该被 2D/3D 拖下水）
③ 关并行 → ARTIFACT_PARALLEL_ENABLED=false

为什么模型要分三档？成本与延迟差一个量级。路由/评估/正文用轻量档（正文是自然语言， 学生看不出措辞差异，但首字速度差 20 倍）；产物要输出强结构 JSON，字段错一个整份作废，所以单独一档可调； 重档留作回退目标与将来更复杂任务的落点。

三个必踩的坑

坑一：127.0.0.1:5173 打不开

Vite 绑的是 IPv6 的 ::1。用 http://localhost:5173。 如果你在写自动化脚本，curl 127.0.0.1:5173 会失败，要用 curl localhost:5173。

坑二：npm run build 报 SAFE_DELETE_BULK_CONFIRM_REQUIRED

这是构建工具清理旧 dist 目录时被安全守卫拦了（文件数超过阈值）。 不是代码问题。手动删掉 frontend/dist 再跑一次即可： 

# Windows PowerShell
Remove-Item -Path frontend\dist -Recurse -Force

# 然后重新构建
cd frontend; npm run build

坑三：端口被占用

ERROR: [Errno 10048] error while attempting to bind on address——说明 8000 端口有别的程序在用。 换个端口：uvicorn app.main:app --reload --port 8001， 同时改 frontend/vite.config.ts 里的代理目标。

附加：数据"丢了"

SQLite 的相对路径锚定在 backend/ 目录。 如果你有时用 uvicorn --app-dir backend（工作目录是项目根），有时用 cd backend && uvicorn， 两种方式会落到两个不同的 app.db，表现为"上传过的 PDF 重启后不见了"。 固定用 cd backend 再启动。

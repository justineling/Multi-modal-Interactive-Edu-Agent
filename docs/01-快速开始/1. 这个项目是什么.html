它要解决的真实问题

假设一个马来西亚中学生要学 KSSM Form 4 历史课本第 4.1 节「Malayan Union 对苏丹的影响」。 他去问通用 AI，会得到一段还不错的文字。但这段文字有三个致命问题：

  • 不知道是不是课本要的答案。AI 讲得可能比课本更全面，但考试按课本评分。学生答得越"全面"，越可能答偏。
  • 没法核对。AI 说的每句话，学生无法快速定位到课本第几页去验证。不可核对的内容，学习时不敢信。
  • 纯文字讲不清结构和过程。疆域怎么变的、权力怎么转移的、地形怎么影响战局的——文字描述再多，也不如一张会动的图。

这个项目针对这三点分别给了答案：

问题这个项目的做法
怕答偏 双模式回答：syllabus_strict（严格按课本，每句带页码）与 hybrid_extended（课本基准 + 明确标注的超纲拓展）。默认前者。
没法核对 每条事实陈述强制带 [p.94] 这样的页码引用，点开能看到课本原文片段。检索不到就明确说「课本未覆盖」，禁止编造页码。
讲不清结构 根据知识点属性自动选形态：离散知识点→PPT，随时间演变→2D 动画，需要空间想象→3D 场景。

和「聊天框式 AI 助教」的三个本质区别

区别一：产物是「活的」，不是一个静态回答

普通 AI 生成一份 PPT，你只能说"重做一遍"。这个项目里，学生点 PPT 第 3 页，输入框自动挂上一个锚点标签： 

┌─────────────────────────────────────────┐
│  针对「第 3 页 · 公民权条件」追问…      │  ← 锚点已绑定
│  ℹ 回答将只更新该节点，其余页面不动      │
└─────────────────────────────────────────┘

提交后，后端只返回一个 update_node 补丁，前端只改那一页。**其余 5 页字节级不变**。 这不是优化，是产品逻辑——学生改一页，不该让整份 PPT 重新生成、丢掉前面调好的内容。

区别二：形态由系统判断，不是用户选

用户不需要知道"这个知识点该用什么形式呈现"。系统根据问句语义路由： 

"Malayan Union 对苏丹的影响有哪些"   → PPT（离散有序，逐条阅读）
"马来半岛各州如何逐步被纳入联邦"     → 2D 动画（随时间演变的空间过程）
"议会大厦的内部结构是怎样的"         → 3D 场景（需要空间想象）

而且每次都会给一句人话理由（如"问句命中「影响」，属于离散有序、需要逐条阅读的信息 → PPT 课件"）， 显示在对话里。用户如果不同意，可以说"用 3D 展示"，系统 100% 遵循。

区别三：回答的边界是显式的，不是模糊的

检索后先做一次相关性评估，输出三种状态之一：

状态含义系统行为
SYLLABUS_MATCH 课本里有，且足以回答 严格依据课本切片生成，每条带页码
PARTIAL_OR_BEYOND 课本提了一点，但问题更深 双层回答：第一层课本基准（带页码），第二层「深度拓展」用琥珀色引用块明确隔开
NO_MATCH 课本完全没覆盖 明确说「课本未覆盖」，引用列表为空，正文不出现任何页码

NO_MATCH 这条是产品的生命线。如果系统对"为什么天空是蓝色的"也回一段带页码的历史课内容， 学生就会开始怀疑所有引用——那整个「严格按课本」的卖点就崩了。所以判定逻辑必须足够严格， 详见 检索与路由。

三种产物分别对应什么知识类型

PPT 课件
6 种布局：标题页 / 要点 / 对比 / 时间轴 / 因果链 / 随堂测验
2D 推演动画
关键帧 + 元素补间，可拖时间轴、逐帧步进
3D 空间场景
几何体组装 + 悬浮标注点 + 相机导览
产物适合什么具体例子
PPT 离散、有序、需要逐条记住的信息 影响有哪几条、两个制度的差异对比、事件的时间顺序、考自己一道题
2D 动画 随时间演变的过程、路径、力的分解 疆域逐步扩张、航线开辟、权力从苏丹转移到总督、受力分析
3D 场景 需要空间想象的结构 建筑内部布局、地形与战局关系、机械结构、分子构型

整个系统最核心的一条设计原则

绝对禁止让大模型直接生成 HTML / Three.js / Manim 源码。

这是全项目最重要的一条约束。原因很实在：让 LLM 直接写 Three.js 代码，十次有八次会出现镜头穿模、 材质丢失、语法崩溃。让它在服务端跑 Manim 渲染视频，要 30~60 秒，学生早关了。

所以采用受控 DSL 驱动渲染：

LLM 只填 JSON
SlideDeckSpec / Keyframe2DSpec / SceneGraph3DSpec
↓
Pydantic 强校验
结构不对直接拒绝，不让坏数据进前端
↓
前端策略分发渲染
按 type 选渲染器，毫秒级出图，100% 不崩

这样做的三个直接收益：零编译等待（不用等打包）、不会崩（渲染器是确定性代码， 不是模型临时写的）、天然可交互（每个元素都是 React 组件，能点击能 hover）。

代价是：JSON 契约必须设计得足够表达力。这是整个项目最需要小心维护的部分， 详见 DSL 契约。

技术栈与目录结构

选型原则是「AI 代码生成准确率最高 + 单机可拉起 + 前后端类型完全对齐」，不追求架构先进。

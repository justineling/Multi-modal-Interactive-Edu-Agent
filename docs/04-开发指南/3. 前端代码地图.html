数据流向

严格单向：事件 → hook → API → store → 组件重渲染。组件之间不直接传数据，全走 store。

用户操作（点击/输入）
    ↓
组件回调（onSend / onSelectNode）
    ↓
hook（useChatStream / useArtifactPatch / useDocumentPolling）
    ↓
api/（client.ts / sse.ts）  ←→  后端
    ↓
store（useWorkspaceStore）  ← 唯一状态源
    ↓
订阅了对应 slice 的组件自动重渲染

为什么组件不直接调 API？因为一个操作往往涉及"请求 + 多个状态更新 + 错误处理"。 如果散在组件里，同一逻辑会在多处重复。抽到 hook 里，组件只剩"长什么样"。

三个核心 hook

hook职责关键点
useChatStream 发起对话流、分发 8 类 SSE 事件 AbortController 幂等守卫（防 StrictMode 双发）
useArtifactPatch 应用补丁、指纹自检 update_node 必须字段级 merge
useDocumentPolling 轮询解析进度 五态状态机，终态停止轮询
useWorkspaceSession 刷新恢复会话 从 localStorage 读 workspace_id，拉 messages 回填

Zustand store 结构

打开：src/store/useWorkspaceStore.ts

状态说明
workspaces / currentWorkspaceId工作区列表与当前选中
documents当前工作区的文件（含解析状态）
messages对话历史（流式时逐 token 追加）
artifacts / activeArtifactId产物列表与画布当前显示的那个
activeVersion当前查看的版本（null = 最新）
anchor锚点：{artifact_id, node_path, node_label, page, section_code} 或 null
demoMode是否演示模式（顶栏黄标）
isStreaming是否正在生成（禁用输入框）

三个性能要点

  1. appendToken 只替换目标消息对象，其余保持引用不变。 否则每来一个 token，整棵消息列表都重新渲染，长会话会卡。
  2. 用选择器而不是整个 store。useWorkspaceStore(selectActiveArtifact) 只在对应 slice 变化时重渲染。
  3. 不要在 store 里发请求。store 只存状态和纯更新函数。 发请求留在 hook，这样 store 可测试、可序列化。

anchor 是最容易出错的状态。它跨了两个组件树： 右栏点击设置它（setAnchor），左栏 Composer 读它（显示 chip）， 发送时带进请求体，发送后要不要清空取决于场景（追问后通常保留，用户可能连续追问同一页）。

目录职责

目录职责约束
types/ 与后端 Pydantic 严格对应的 TS 接口 纯类型，不含逻辑。可选字段写 T | null
api/ HTTP 客户端 + SSE 解析器 统一 unwrap() 拆包，非 OK 抛类型化错误
store/ 全局状态 只存状态 + 纯更新函数，不发请求
hooks/ 业务逻辑 可以调 api、改 store
components/ UI 不直接调 api（除了极简单的查询）
lib/ 纯函数工具 无 React 依赖，可单独测试

lib/ 里的四个纯函数模块

文件职责
jsonPointer.tsresolve / setAtPath / isAncestorOrSelf（必须用 / 边界判断）
fingerprint.ts确定性序列化 + sha256，用于补丁自检
anim2d.ts归一化坐标（0~1000 × 0~600）→ 实际像素换算
scene3d.ts3D 节点父子层级、相机插值

三种渲染器的实现要点

SlideRenderer（PPT）

策略模式：LAYOUT_REGISTRY 把 layout 字符串映射到组件。

const LAYOUT_REGISTRY = {
  title_hero:    TitleHeroLayout,
  bullet_points: BulletPointsLayout,
  comparison:    ComparisonLayout,
  timeline:      TimelineLayout,
  cause_effect:  CauseEffectLayout,
  quiz:          QuizLayout,
};

// 分发 + 兜底
const Layout = LAYOUT_REGISTRY[slide.layout] ?? BulletPointsLayout;
要点说明
16:9 固定比例用 CSS aspect-ratio + 容器宽度，不写死像素
缺字段降级如 comparison 但 comparison_left 为 null → 回退成要点列表样式，不白屏
超长文本截断20 条 bullets 只显示前 N 条 + 「…等 N 条」
ErrorBoundary单个页面渲染崩了，不能拖垮整个工作区
点击回传路径点页面 → setAnchor({node_path: "/slides/${i}"})

Anim2DRenderer（2D 动画）

要点说明
坐标换算AST 是归一化 0~1000×0~600，渲染时乘容器尺寸。注意 devicePixelRatio
补间GSAP 在关键帧之间插值，不是瞬移
分层背景 / 元素 / 交互三个 Konva Layer，不要一个 Layer 全画（性能）
5 种 shapecircle / rect / arrow / label_box / zone
时间轴播放/暂停/拖拽/逐帧，拖拽只改一个 index，不重建画布

Scene3DRenderer（3D 场景）

要点说明
按需加载three.js 1.15MB，用 React.lazy 拆成独立 chunk
Suspense 骨架屏首帧加载期间不能白屏
6 种 primitivebox / sphere / cylinder / cone / terrain_plane / arrow_link
相机平滑点标注点后，useFrame 里 lerp 插值，不是瞬切
父子层级parent_id 存在时用相对坐标嵌套
简化渲染低性能设备关阴影、降 segment

版本锁定不是建议： @react-three/fiber 必须 v9（v8 与 React 19 不兼容，装了整块 3D 白屏）、 react-konva 必须 19、tailwindcss 必须 3.4（v4 是 CSS-first 配置，写法完全不同）。 改 package.json 前先确认兼容性。

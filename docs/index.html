多模态沉浸式智能助教

一套「对话驱动的富媒体生成式学习工作区」的完整文档。上传教材，系统自动生成 PPT / 2D 推演动画 / 3D 空间场景； 点画布上任意一页、一个元素、一个部件即可追问，系统只改那一处，不推倒重来。

这套文档面向三类人，请按你的身份选入口。内容有重叠，但顺序和深度不同——不必全读。

接手开发？先读项目根目录的 HANDOVER.md。 里面有「回家三步走」（怎么把代码拿到另一台机器）、代码地图（改什么去哪）、按优先级排的待办清单、 六个必踩的坑、以及「下次开工第一件事」。

这份 HTML 文档站是深度参考；HANDOVER 是快速恢复上下文的入口。 下班后重新开工，读 HANDOVER 比读这里快得多。

增量文档：真实模式耗时优化（P1-03）

上面 21 篇是系统级文档，随代码长期有效。这一组是一次具体改造的过程记录—— 包括需求、设计、实测数据、被数据否掉的方案、以及 QA 的独立验证。

它们回答的是「为什么现在是这个样子」：为什么产物用轻量模型、为什么不做分批下发、 为什么 TTFT 的 fork 点放在首 token 之后。改性能相关代码前值得先读。

源文档（Markdown）

文档站是这些源文档面向不同读者的重组版本。源文档保留原始语境 （含勘误、含「此处已推翻」的历史判断），文档站负责「现在该怎么用」——两者都要留。

全部收在 docs/00-源文档/， 每个文件的定位见下表：

文件是什么什么时候看
SPEC.md 需求方原始规范，不可篡改。冲突时优先级最高 怀疑需求被理解偏了
PRD.md 12 条 P0 需求 + 可测试的验收标准 判定「做完没有」
ARCHITECTURE.md 架构、模块划分、数据模型、任务分解 改架构 / 加模块
IMPL-NOTES.md 踩坑与裁定记录（E1~E12），记的是「为什么这么写」 改代码之前
QA-REPORT-backend.md P0 逐条验收结论 + 8 个缺陷 + 遗留风险 R1~R8 查「验过什么、漏了什么」
class-diagram.mermaid 数据模型类图（7 张表、AST 契约、服务层接口） 看表结构与契约关系
sequence-diagram.mermaid 一次提问的时序图（含降级链路 C） 看调用链与失败路径

最该先读的是 IMPL-NOTES.md—— 它记的是「为什么这么写」，比「写了什么」更能防止你把已经修好的 bug 改回去。

与 docs/increments/ 的区别：本目录是项目级基线（改了就改）， increments/ 是单次迭代的过程记录（只增不改，历史快照）。

项目一句话说明

传统 AI 助教是「聊天框 + 一段文字」。这个项目的核心判断是：纯文字讲不清结构和过程。 历史课本里的疆域变迁、物理里的受力分解、生物里的代谢流程，文字描述再多也不如一张会动的图。

所以它把回答形态扩展成三种：PPT（离散有序的知识点）、2D 动画（随时间演变的过程）、 3D 场景（需要空间想象的结构）。而且这三种产物都是「活的」——你能点进去追问，系统只改那一处。

如果你是第一次接触这个项目，建议顺序：
① 这个项目是什么 → ② 环境搭建与运行 → ③ 一次提问的完整旅程。 走完这三篇，你对整个系统的理解会超过读十篇零散笔记。
